## OpenAI — public context, limited storage evidence

The fleet-scaling account establishes public AI infrastructure context. It does not reveal a full private artifact-store protocol. Original practice: size checkpoint fan-out and restore paths without inventing private internals. Explain useful restored work, rather than equating occupied accelerators with progress.

## Anthropic — public workflow context

The multi-agent article grounds coordination and artifact-oriented workflow context. It does not specify a private object catalog or deletion protocol. Original practice: preserve provenance, scope access, distinguish untrusted artifacts from trusted instructions, and publish complete versions through explicit authority.

## Meta — historical storage engineering

The Tectonic publication describes consolidated storage, disaggregated metadata, and tenant performance concerns. Original practice: compare metadata scale, bulk-byte scale, and isolation. Our sample counts, assumed metadata sizes, coding layout, and architecture are invented exercises, not Tectonic measurements or defaults.

## Google — historical file-system research

GFS provides a primary historical example of workload-driven distributed file-system design. Original practice: ask which namespace and mutation semantics the application actually needs. Do not apply historical semantics to every modern Google service or treat an object-store adapter as universally POSIX-compatible.

## NVIDIA — versioned checkpoint documentation

NeMo documents distributed checkpoint concepts including sharded state and loading concerns. Original practice: separate weights-only inference artifacts from complete training continuation, and include topology remapping in restore analysis. The lesson's restore rates and manifest protocol are independent proposals.

## Supporting standards of evidence

AWS documents S3's actual consistency scope; this does not create an arbitrary transaction over an application dataset. HDFS provides a concrete file-system architecture reference. Ceph grounds failure-domain-aware placement; our simplified repair arithmetic is not a claim about its implementation. Durability probabilities require a failure and repair model beyond replica or code ratios.

## Staff+ exercises and limits

Defend partial upload, competing publishers, lost commit response, collector race, old reader, corrupt fragment, missing decryption key, and regional catalog/object mismatch. Evaluation covers consistency unit, authority, identities, workload arithmetic, security, restore feasibility, costs, and evolution. Local Python assertions validate the educational transition model only; no production durability or performance claim follows.
