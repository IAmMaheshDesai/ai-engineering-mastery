## Technical sources and chapter mapping

1. Martin Kleppmann, *How to do distributed locking*, February 8, 2016. The paused lease holder and receiver-enforced token illustrate why application pauses and delayed messages matter. Chapters 1 and 4 extend the example by explicitly separating allocation, installation and acknowledgment. https://martin.kleppmann.com/2016/02/08/how-to-do-distributed-locking.html

2. Kubernetes maintainers, *client-go/tools/leaderelection*, Go package documentation. The package discusses leader election, clock-rate assumptions and its lack of a fencing guarantee. Chapter 3's numerical rate calculation is an independent bounded-clock example, not a claimed implementation of client-go. https://pkg.go.dev/k8s.io/client-go/tools/leaderelection

3. etcd project, *API reference: concurrency*, version 3.4. The lock service returns a key that can participate in a transaction protecting changes to etcd. Chapter 5 contrasts this shared transaction boundary with an asynchronous external provider. The lock key is not presented as an automatically enforced token for arbitrary systems. https://etcd.io/docs/v3.4/dev-guide/api_concurrency_reference_v3/

4. Mike Burrows, *The Chubby Lock Service for Loosely-Coupled Distributed Systems*, OSDI 2006, especially the discussion of sequencers and lock delays. The API and client obligations motivate chapters 4–5. https://www.usenix.org/legacy/event/osdi06/tech/full_papers/burrows/burrows_html/

5. Diego Ongaro and John Ousterhout, *In Search of an Understandable Consensus Algorithm*, USENIX ATC 2014, extended version. Chapter 2 separates replica election terms from application-specific grants stored in replicated state. https://pdos.csail.mit.edu/6.824/papers/raft-extended.pdf

## OpenAI

6. OpenAI, *Scaling Kubernetes to 7,500 nodes*, January 25, 2021. The engineering account describes the scale and characteristics of a research cluster. It motivates studying the load produced by periodic coordination traffic. https://openai.com/index/scaling-kubernetes-to-7500-nodes/

Original exercise. Explain why monitoring 128,000 agents and durably renewing 4,000 planning grants can use different paths. Defend a safe scheduling policy for an isolated node without implying that this policy describes OpenAI's implementation.

## Corrections and remaining uncertainty

The lesson corrects three recurrent mistakes: granting a new epoch does not establish that every external sink has installed it; a UUID can enforce equality after a trusted installation even though it does not prove numeric order; and idempotency does not reject a different intent from an obsolete owner. The illustrations are original, with the classic paused holder example credited to source 1. No provider guarantee or internal OCI recovery architecture is assumed. Production use would require verifying each provider's atomicity, cancellation, durability and deduplication contracts.
