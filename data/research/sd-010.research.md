## OpenAI

5. OpenAI, *Tracing*, Agents API documentation, publication date unspecified. The public documentation describes traces showing model responses, tool calls and delegated work. This establishes an observability use case. It does not establish that traces are an event-sourced authority or that a provider action can be safely repeated. https://developers.openai.com/api/docs/guides/agents-api/tracing

Original practice. Specify which observed tool result is diagnostic evidence and which accepted application fact justifies resuming an external operation. Defend a recovery API after losing a provider response.

## Meta

8. Meta Engineering, *Open-sourcing LogDevice: A distributed data store for sequential data*, September 21, 2018. ## Clarifications and original work

A trace or audit feed can record events without being the canonical source for application state. CQRS can use one database and does not require event sourcing. Expected revision checks alone do not recover a previously accepted command result. A snapshot hash alone does not prove that its serialized state covers the labeled revision. Chapters 1, 3, 4 and 6 clarify these points. All drawings and state traces are original. The two Python panels model pure transitions and a contiguous projection checkpoint; storage atomicity, network failure and provider guarantees require additional implementation and validation.
